# Cookie Patrol 데모 시나리오

이 데모는 교육용 가짜 배송 알림, 계정 보안 페이지, 경품 광고를 사용합니다. 실제 피싱 사이트로 이동하지 않고, 이름·계정·인증번호를 입력받거나 저장하지 않습니다. `192.0.2.0/24` 주소는 문서 예제용이며, 단축 URL은 텍스트로만 표시합니다.

## 1. 백엔드 실행

Google Safe Browsing API 키를 `SAFE_BROWSING_API_KEY` 환경 변수에 설정한 뒤 실행합니다. 키는 저장소에 추가하지 마세요.

```powershell
cd backend
uv run fastapi dev app/main.py
```

에뮬레이터에서 Android 앱은 기본값 `http://10.0.2.2:8000`으로 백엔드에 접속합니다. 실제 폰에서는 PC의 로컬 네트워크 주소를 빌드 속성으로 전달합니다.

```powershell
cd frontend
./gradlew.bat -PcookiePatrolApiBaseUrl=http://192.168.0.10:8000 assembleDebug
```

예시 주소를 PC의 실제 로컬 네트워크 주소로 바꾸고, 폰과 PC를 같은 네트워크에 연결하세요. 앱의 Android 매니페스트는 데모를 위해 HTTP 통신을 허용합니다.

## 2. 데모 페이지 실행

별도 PowerShell 창에서 저장소 루트 기준으로 실행합니다.

```powershell
powershell -ExecutionPolicy Bypass -File demo/serve.ps1
```

에뮬레이터 브라우저에서 아래 페이지를 열 수 있습니다. 실제 폰에서는 서버 스크립트가 표시하는 PC 주소에 `:8765`를 붙여 사용합니다. Windows 방화벽이 접근을 막으면 개인 네트워크에서만 이 서버의 접속을 허용하세요.

| 경로 | 시나리오 | 기대 신호 |
|------|----------|----------|
| `/` | 가짜 배송 안내 | 택배 문구, HTTP, 숫자 IP, APK |
| `/account-security` | 가짜 계정 보안 안내 | 계정 제한 압박, HTTP, 숫자 IP, APK |
| `/reward-ad` | 텍스트형 가짜 경품 광고 | 당첨 문구, 단축 URL |
| `/image-ad` | 이미지 안에만 문구가 있는 광고 | OCR의 당첨 문구, 단축 URL |

예: 에뮬레이터에서 `http://10.0.2.2:8765/reward-ad`를 엽니다. 각 주소와 광고 문구는 교육용이며 실제 사이트로 연결되지 않습니다.

## 3. Android 경고 확인

1. 앱을 설치하고 알림 표시와 문자·카톡 알림 감시 권한을 켭니다. 메시지 카테고리가 지정된 알림과 Android 기본 문자·카톡 앱 알림을 검사합니다. 앱이 메시지 카테고리를 지정하지 않고 기본 앱 목록에도 없으면 해당 알림은 검사하지 않습니다.
2. 화면 속 글자를 시험하려면 앱의 **화면 감시 켜기**를 눌러 데모용 접근성 서비스를 켭니다.
3. 위 표의 데모 페이지를 각각 브라우저에서 엽니다. 세 페이지는 서로 다른 위험 신호 조합으로 로컬 경고가 떠야 합니다.
4. 다른 기기에서 다음 문장을 문자로 보내거나, 이 문장 그대로 보이는 알림을 생성해 알림 감시도 확인합니다.

```text
[배송 안내] 주소가 맞지 않아 택배가 보류됐습니다. 확인: http://192.0.2.1/parcel.apk
```

5. 정상 알림 예시로 `내일 회의 자료 https://docs.google.com/abc 확인 부탁드려요`를 보내고 위험 경고가 뜨지 않는지 확인합니다.
6. 일반 광고 문구 `오늘 하루 20% 할인 쿠폰을 드려요. https://shop.example.com/event`는 경고를 만들지 않는 대조 사례입니다.

## 4. 실기기 시연 점검표

아래 항목은 설정이 실제 기기에서 동작하는지 확인한 뒤 표시하세요. 에뮬레이터 확인만으로 실기기 항목을 완료 처리하지 않습니다.

- [ ] 앱 알림 권한을 켜고 데모 경고 알림이 뜨는지 확인합니다. 경고 알림을 눌렀을 때만 큰 글씨 안내 화면이 열립니다.
- [ ] 알림 접근 권한을 켜고 위험 문자 예시에서는 경고가, 정상 문자 예시에서는 경고가 뜨지 않는지 확인합니다.
- [ ] 접근성 설정에서 화면 감시를 켜고 데모 페이지를 열어 `택배`, `http`, 숫자 주소, `.apk` 신호가 읽히는지 확인합니다. 화면 변경을 0.35초 동안 모은 뒤 스크린샷은 최소 1초 간격으로 검사합니다.
- [ ] `/account-security`에서 계정 보안 안내와 숫자 IP 링크 신호가 읽히는지 확인합니다.
- [ ] `/reward-ad`에서 당첨 문구와 단축 URL 신호가 읽히는지 확인합니다.
- [ ] `/image-ad`를 열어 이미지 안에만 있는 당첨 문구와 단축 URL을 OCR로 감지하는지 확인합니다.
- [ ] 다운로드 감시를 켜고 테스트용 `.apk` 파일을 다운로드해 안내가 뜨는지 확인합니다. 파일은 설치하지 않아도 됩니다.
- [ ] 테스트 기기에 원격제어 앱을 설치하는 경우, 설치 직후 경고가 뜨는지 확인합니다. 현재 앱 이름 기반이 아니라 아래 패키지 ID를 기준으로 즉시 경고합니다.
  - `com.teamviewer.quicksupport.market`
  - `com.anydesk.anydeskandroid`
  - `com.rsupport.mobizen.cn`
  - `com.rsupport.remotemeeting.application`
- [ ] Safe Browsing 키를 설정하지 않거나 백엔드 연결을 끊어도 이미 표시된 로컬 경고가 사라지지 않는지 확인합니다.

접근성 기능은 화면에 노출된 텍스트와 OCR이 이미지에서 읽은 문구를 기기 안에서 검사합니다. OCR 이미지는 저장하거나 서버로 전송하지 않고 처리 직후 버립니다. 화면 전체를 읽을 수 있는 것은 아니며 보안 화면은 Android가 캡처를 막을 수 있습니다. Cookie Patrol 화면의 이벤트는 무시하고, 화면이 빠르게 바뀌면 마지막 화면을 모아 최소 1초 간격으로 검사합니다. 접근성 텍스트는 최대 500개 요소·12,000자까지 처리합니다. OCR은 QR 코드 자체를 해석하지 않습니다.

평판 조회는 위험 신호 2점부터 하고, 즉시 로컬 경고는 3점부터 합니다. 따라서 의심 문구와 HTTPS 링크가 함께 있어도 경고 기준보다 낮으면 Safe Browsing 결과가 위험일 때 경고가 추가됩니다. 조회되지 않았다는 결과는 안전 보증이 아닙니다.

다운로드·앱 설치 감시는 알림 접근 서비스가 연결되어 있는 동안 동작합니다. Android 버전과 제조사 설정에 따라 서비스가 중단되거나 파일 정보를 읽지 못할 수 있으므로, 시연 기기에서 각각 확인하세요.

## 5. 기대 결과와 한계

- 의심 문장과 데모 페이지에서는 로컬 위험 신호 경고가 즉시 나타납니다. 실제 앱 설치나 개인정보 입력은 일어나지 않습니다.
- Safe Browsing에 등록되지 않은 데모 주소는 `dangerous: false` 또는 조회 불가 시 `unknown`이 될 수 있습니다. `false`는 안전 판정 보증이 아닙니다.
- 서버 조회 실패나 API 키 누락으로도 로컬 경고가 사라지지 않아야 합니다.
- 의심 URL의 전체 주소는 백엔드와 Google Safe Browsing으로 전송됩니다. URL의 경로·쿼리에 개인 정보나 토큰을 넣지 마세요. 서버 캐시는 주소 원문 대신 SHA-256 키를 저장하지만, 이는 익명화가 아닙니다.
- 이 페이지는 교육용 시뮬레이션입니다. 실제 문자 앱·제조사별 접근성 트리·알림 형식은 폰에 따라 다르므로 실기기 확인이 필요합니다.

## 6. 자동 확인

저장소 루트에서 Android 점수 단위 테스트와 디버그 APK 빌드를 실행합니다.

```powershell
cd frontend
./gradlew.bat testDebugUnitTest assembleDebug
```

백엔드 테스트는 다음과 같습니다.

```powershell
cd backend
uv run pytest
```
