# Cookie Patrol 개발 진행 요약

## 프로젝트 목적

Cookie Patrol은 피싱 문자와 의심 링크를 어려운 보안 용어 없이 알려주는 안드로이드 데모 앱이다. 위험을 설명하고 안전한 행동을 안내하되, 사이트나 앱 사용을 강제로 차단하지 않는다. 글자를 크게 쓰고 한 화면에 필요한 정보만 보여주는 것을 기본 원칙으로 삼는다.

## 구현한 기능

### Android 앱

- Kotlin과 Jetpack Compose로 홈, 보호 설정, 큰 글씨 경고 화면을 구성했다.
- Android 알림 접근 서비스를 이용해 문자·카카오톡 등 대상 알림의 문구와 링크를 기기 안에서 검사한다.
- 링크 단축 서비스, HTTP, 숫자 IP, APK 주소, 계정 정지 압박, 인증번호·비밀번호 요구, 급한 송금, 가족 사칭, 주민등록번호 요구 등 피싱 위험 신호를 점수화한다.
- 위험 신호가 충분하면 경고 알림을 보낸다. 경고 알림을 눌렀을 때 상세 화면을 열며, `확인했어요`는 화면만 닫는다.
- APK 다운로드와 일부 원격제어 앱 설치를 감시하는 데모 기능을 추가했다.
- 데모용 접근성 서비스는 현재 화면의 접근성 텍스트와 기기 내 한국어 OCR 결과를 함께 검사한다. 이미지 캡처는 저장하거나 서버로 보내지 않는다.
- 권한 상태를 앱 복귀 때 다시 읽고 홈 화면에 표시한다.

### URL 평판 확인 백엔드

- FastAPI `POST /check`에서 Google Safe Browsing을 먼저 조회하고, 미등록 또는 조회 실패 시 설정에 따라 OpenAI 분석을 이어간다.
- 앱에는 공급자 API 키를 넣지 않는다. 결과를 캐시해 외부 호출을 줄인다.
- URL 주소 형식과 위험한 입력을 검사하고, 동시 조회 수·URL 개수·요청 빈도를 제한한다.
- IP별 요청 제한과 재시도 응답을 적용했다. 조회 실패와 제한 응답은 `unknown`으로 처리하며 기존 로컬 경고를 지우지 않는다.
- SQLite 판정 캐시와 Safe Browsing 메모리 캐시에 크기 제한과 만료 정리를 적용했다.
- 릴리스 앱은 HTTPS만 허용하고, 디버그 빌드에서만 에뮬레이터 백엔드 HTTP 주소를 허용한다.

### 피싱 데모와 회귀 검증

- 실제 사이트에 연결하지 않는 가짜 배송 안내, 계정 보안 안내, 경품 광고 및 이미지형 광고 페이지를 만들었다.
- 위험 문구뿐 아니라 정상 메시지와 일반 광고를 대조 사례로 추가했다.
- URL user-info, 국제화 도메인, URL 길이·개수 제한, 알림 필터, OCR 입력 예산, 일시적 조회 실패 재시도, 요청 제한과 캐시 동작에 대한 회귀 테스트를 추가했다.

## 디자인 시안

디자인 검토를 위한 인터랙티브 웹 목업을 `design/cookie-patrol-concept.html`에 추가했다. 홈·권한 안내·위험 경고 화면을 전환할 수 있고, 큰 글씨와 권한 상태, 다운로드 감시의 알림 접근 의존성, 선택형 화면 감시, 개인정보 흐름을 표현한다. 브라우저에서 `design/preview-server.js`를 실행하면 `http://localhost:8765/`에서 볼 수 있다.

이 목업은 화면 검토용이다. Android 앱의 Compose UI에 반영되거나 Android 권한을 실제로 요청하지 않는다.

## 남은 작업

- 데모 폰에서 다운로드 감지, 원격제어 앱 패키지명, 접근성 화면 읽기와 이미지 OCR을 직접 확인한다.
- 이용약관의 면책, 개인정보, 저작권 및 사용 범위 문구를 확정한다.
- 앱 심사와 배포 환경에 맞게 접근성 기반 화면 감시 등 데모 전용 권한의 출시 범위를 결정한다.
