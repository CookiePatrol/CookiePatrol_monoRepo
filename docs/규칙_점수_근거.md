# 규칙과 점수의 근거

규칙 구현은 `frontend/app/src/main/java/com/cookiepatrol/detect/RiskAnalyzer.kt`, 합산과 임계값은 `LocalAssessment.kt`의 `RiskAnalyzer`다. 규칙별 ID는 평가 보고서의 `signals`와 일치한다. 테스트 파일은 `SignalsTest.kt`, `EvaluationTest.kt`이며, 아래 ID는 합성 데이터 원본에서 확인할 수 있다. 점수는 위험 확률·통계적으로 학습한 계수·기관 권고 점수가 아니다.

단어가 들어갔다는 사실과 사기라는 결론은 다르다. 서로 다른 묶음 메시지를 한 문장으로 합치지 않도록 `NotificationText.parts`에서 분리한다. 실제 알림 제목은 일반적으로 발신자·대화방일 수 있으므로 본문이 있을 때 제목을 위험 문맥에 합산하지 않는다. 제목만 있는 알림은 별도로 검사하므로 형식별 실기기 확인이 필요하다.

## 2점 조회와 3점 경고

원본 `PLAN.md`와 코드 모두 약한 신호 2점이면 URL을 조회하고, 3점부터 로컬 경고한다. HTTPS+유인 단어처럼 2점인 사례도 추가 검사하기 위한 설계다. 3점은 IP/APK/user-info/신분번호 요구 같은 하나의 강한 신호, 또는 HTTP 1점+유인 단어 2점 같은 조합으로 경고하려는 초기 설정이었다. 이를 정한 당시의 실험·회의 기록은 저장소에서 확인하지 못했다. 사후 설명을 검증된 최적값처럼 발표하면 안 된다.

이번 도구는 개발용 60개에서 경고 2/3/4점, 조회 1/2/3점, 송금 가중치 2/3점의 18개 설정을 비교한다. 수치는 [평가 실행 결과](evaluation/mock-results.md)의 개발용 설정 비교와 JSON에 있다. 서버 조회 기준을 낮추면 후보가 늘지만 이것만으로 실제 API 효과나 비용을 입증할 수 없다. 송금 가중치 3점은 개발용 합성 문장의 F1을 개선할 수 있으나 정상 송금 요청과의 구분을 충분히 검증하지 못해 채택하지 않았다. 기존 가중치와 2/3점 기준을 유지하고, 확인된 금지 안내 오탐만 수정했다.

평가용 60개에서 원본 대비 FP 4→1, TP 20→20, FN 10→10이다. 규칙 변경 전후를 동일한 고정 원본 규칙과 비교한 결과다. 이 개선을 실제 사용자 피해 감소율로 환산할 수 없다. 새로운 어휘, URL 없는 사칭, 낮은 점수의 위장 주소는 여전히 놓친다.

재점검에서 개발/평가 사이에 의미가 유사한 정상 문구 4쌍을 발견했다. 따라서 위 결과는 합성 회귀 시험이며 독립 성능 개선의 증거가 아니다. 관련 평가 ID 4개를 사후 제외한 56개에서 원본/수정은 모두 TP20·FP0·TN26·FN10이다. 이 부분집합 역시 대표 정확도가 아니다. 문구·라벨을 별도 작성자가 검토한 새 독립 평가가 필요하다([재점검 결과](재점검_결과.md)).

기술적 입력 범위의 근거는 [Android Notification](https://developer.android.com/reference/android/app/Notification), [NotificationListenerService](https://developer.android.com/reference/android/service/notification/NotificationListenerService), [Android 15 OTP 알림 보호](https://developer.android.com/about/versions/15/behavior-changes-all#otp-notifications)다. 형식 지원을 구현하고 합성 필드로 시험했지만, 특정 카카오톡·삼성 메시지 버전의 실제 extras를 수집해 확인한 것은 아니다.
