# 평가 실행과 해석

자동 테스트 통과 수는 피싱 탐지 정확도가 아니다. 로컬 규칙 평가는 합성 문장 시험이며, 외부 고정 응답 비교는 **모의 시험**이다. 실제 Google·OpenAI 탐지 성능은 현재 **미측정**, 실제 API 비교는 **미실행**이다.

## 준비와 전체 재실행

환경: Windows PowerShell, JDK 17, Android SDK 35, Python 3.12 이상. 현재 검증은 Python 3.12.15, Gradle 8.14.1, AGP 8.11.1, Kotlin 2.2.0에서 수행했다. SDK 경로는 `ANDROID_HOME`으로 지정한다. PyCharm에서는 해당 모듈의 SDK를 사용한다.

저장소 루트에서 최초 한 번 백엔드 의존성을 준비한다.

```powershell
Push-Location backend
uv sync
Pop-Location
```

키 없이 전체 검증을 실행한다. `verify.ps1`은 외부 Google·OpenAI 요청을 하지 않는다. Gradle 의존성 다운로드는 필요할 수 있다.

```powershell
powershell -ExecutionPolicy Bypass -File scripts/verify.ps1
```

다른 인터프리터를 쓰는 경우 `-PythonExecutable '절대경로/python.exe'`를 지정한다. 테스트→Android 두 빌드·lint→Kotlin 결과를 읽는 모의 평가 순서다. 실패 시 중단한다. 산출물은 다음과 같다.

| 파일 | 의미 |
|---|---|
| `docs/verification/summary.json` | 현재 커밋·브랜치·자동 테스트 수·빌드 상태 |
| `docs/verification/backend.log`, `backend.xml` | 백엔드 실행 원본과 JUnit 결과 |
| `docs/verification/android-current.log`, `android-tests.xml` | Android 실행 원본과 JUnit 결과 |
| `docs/verification/local-results.json` | 실제 Kotlin 규칙·원본 규칙의 점수·신호·URL·JVM 측정 시간 |
| `docs/evaluation/mock-results.md` | 사람이 읽는 모의 비교·혼동행렬·오류 목록·사례별 결과 |
| `docs/evaluation/mock-results.json` | 계산식의 분자·분모, 개발용 후보 설정, 해시 등 전체 결과 |

이전 실행 로그와 현재 로그를 혼동하지 않는다. `summary.json`은 실행 시작 시 `running`, 실패하면 `failed`와 실패 단계로 갱신한다. `passed`인 현재 run_id의 결과만 최종 성공으로 사용한다. 실패한 실행에서 이전 성공 수치가 남지 않는지 별도 의도적 실패 시험을 수행했다(`verification/script-failure-probe.json`). APK SHA-256은 `verification/artifacts.json`에 매번 갱신한다. 원본 커밋의 기준 결과는 `baseline-*` 파일이다.

## 데이터와 분리

`frontend/app/src/debug/assets/evaluation-cases.txt`: 개발용 60개(정상 30, 피싱 의심 30). `holdout-cases.txt`: 평가용 60개(정상 30, 피싱 의심 30). 각 행은 `ID|라벨|유형|분리|라벨 근거|출처|평가 유형|입력`이다. 전부 이번 작업에서 만든 한국어 **합성 데이터**이며 실제 피해자의 문자 수집본이 아니다. 합성 시나리오의 의도를 정답으로 사용하므로, 입력 문장만으로 진위를 구분하기 어려운 사례가 있다. 독립적인 두 명 이상의 라벨 검토가 필요하다.

규칙의 부정문 처리 수정은 개발용 N14·N15에서 정했다. 평가용 문구를 기준으로 가중치를 최적화하지 않았다. 원본 커밋 `70923b4`의 규칙은 `src/test/.../detect/baseline/BaselineRules.kt`에 고정했고, 같은 입력·같은 URL 정규화 절차로 변경 전후를 비교한다.

URL·숫자 정규화 후 문자 4-gram Jaccard 0.45 이상인 개발/평가 쌍을 찾는다. 정확 중복과 유사 후보는 결과에 기록한다. 이는 동일 문장의 변형을 찾는 보조 절차이지 의미적 독립성의 증명이 아니다. 배송 사칭·가족 사칭 같은 공격 유형은 양쪽 모두에 필요하다. 작성자가 같아 문체 편향이 남는다. 평가용을 추가 조정용으로 사용하게 되면 다음 버전에서는 새 평가용을 확보해야 한다.

Kotlin이 데이터·규칙 소스 SHA-256을 기록하고 Python이 재검사한다. 데이터나 규칙을 바꾸고 Kotlin 평가를 다시 실행하지 않으면 결과 생성을 거부한다. 개발용 임계값 비교는 경고 2/3/4점, 서버 후보 1/2/3점, 송금 가중치 2/3점의 18개 조합이다. 전체 가중치 탐색이나 통계적 최적값의 증명은 아니다.

재점검에서 자동 4-gram 기준이 놓친 의미 유사 문구를 확인했다: N14↔EN11·EN24(인증정보를 공유하지 말라는 안내), N15↔EN12(신분번호 입력 금지), N26↔EN06(정상 숫자 서버). `leakage_audit.manual_similarity_findings`에 원문과 이유를 남겼다. 따라서 **독립성은 확보되지 않았고**, 현재 평가는 합성 회귀 시험으로 설명해야 한다. 원본 60개 결과는 유지한다. `similarity_sensitivity`는 위 평가 ID 4개를 사후 제외한 56개이며 원본·수정 모두 TP20/FP0/TN26/FN10이다. 어려운 정상 사례를 제외한 결과를 대표 정확도로 발표하면 안 된다. 새 평가 자료는 개발 문구를 보지 않은 팀원이 별도로 작성·라벨 검토하고 평가 전에 고정해야 한다.

## 지표와 실패

TP=위험 문장에 위험 경고, FP=정상 문장에 위험 경고, TN=정상 문장에 위험 미감지, FN=위험 문장에 위험 미감지다.

| 지표 | 계산식 |
|---|---|
| 정밀도 | TP/(TP+FP) |
| 재현율 | TP/(TP+FN) |
| F1 | 2TP/(2TP+FP+FN) |
| 오탐률 | FP/(FP+TN) |
| 미탐률 | FN/(TP+FN) |
| 판정 완료율 | (TP+FP+TN+FN)/전체 사례 |
| 전체 위험 대비 탐지율 | TP/(TP+FN+판단불가 위험 사례) |

분모 0은 `null`(계산 불가)이다. API 실패·시간 초과·호출 제한·판단 불가를 정상으로 세지 않는다. 주 혼동행렬에서 제외하고 `unknown`, `coverage`, `recall_all_phishing`을 함께 보고한다. 로컬 경고가 이미 있으면 서버 실패로 이를 취소하지 않으므로 위험 판정은 유지된다. 앱은 추가 검사 불가를 주의 안내로 보여줄 수 있으나 이를 모델의 위험 탐지 성공으로 집계하지 않는다.

Google 실패 후 AI가 유효한 응답을 준 경우 최종 URL 결과는 AI 응답을 사용한다. 제공자 실패 기록은 남기지만 이를 최종 판단 불가와 혼동하지 않는다. `provider_outcomes`와 `resolved_url_outcomes`를 구분해 저장하며 이 조합을 별도 모의 회귀 시험으로 확인한다.

실기기 화면은 미수신·판단 불가·미기록을 제외한다. 제외가 많으면 정밀도·재현율만 발표하지 말고 수신 확인 건수와 제외 사유도 발표한다. Python 지표는 손으로 계산한 TP=3, FP=1, TN=2, FN=1, 판단불가=1 사례로 검증했고, Kotlin 지표도 별도 작은 사례로 검증한다.

## 세 구성의 비교 범위

1. 기기 내 규칙: 실제 앱의 `RiskAnalyzer`를 JVM에서 실행한다.
2. 규칙+Google: 점수 2 이상이고 URL이 있는 후보만 조회한다고 가정한다.
3. 규칙+Google+AI: 위 후보에서 Google 위험 미등록/실패 시 AI를 조회한다.

경고는 3점부터이고 로컬 위험 신호는 항상 유지한다. 한 사례의 URL은 최대 10개다. 자동 조회에는 앱의 별도 전송 동의가 필요하며, 비교 도구는 동의한 시험 상황을 가정한다. 0~1점 링크나 링크 없는 요구는 자동 외부 검사에 도달하지 못한다. `EP17`, `EP18`, `EP19`, `EP24`, `EP25`는 모의 AI를 추가해도 자동 후보 선정 때문에 남는 미탐이다. 사용자는 홈의 ‘링크 직접 검사’로 2점 미만 주소도 명시적으로 보낼 수 있다. 직접 검사 결과는 위 자동 파이프라인 수치에 섞지 않는다.

`evaluation-mocks.json`은 사람이 고정한 응답이다. EP20·EP21의 개선, EN21의 악화, EP23의 호출 제한, EP28의 시간 초과는 **의도적으로 구성한 모의 시험**이다. 실제 모델이 그렇게 응답했다는 뜻이 아니다. 논리 조회 횟수와 실제 외부 요청 시도 수를 구분한다. 모의 외부 지연은 0으로 두고 실제 지연이라고 해석하지 않는다. 로컬 시간은 Windows JVM에서 준비 실행 20회 후 사례별 5회 중앙값으로 측정했다. 실기기 지연·배터리 소모는 미측정이다.

## 키를 직접 설정한 후 실제 비교

다음은 팀원이 이후 직접 실행할 절차이며 이번 작업에서는 실제 비교를 실행하지 않았다. `backend/.env.example`의 이름은 `SAFE_BROWSING_API_KEY`, `OPENAI_API_KEY`, `OPENAI_MODEL`이다. 실제 값은 `backend/.env` 또는 환경변수에 설정하고 채팅·Git·로그에 기록하지 않는다. `app/main.py`와 평가 도구는 자신의 파일 위치를 기준으로 `.env`를 읽고 기존 환경변수를 우선한다(`override=False`). `.env`와 `.env.*`는 Git 제외 대상이며 `.env.example`만 추적한다.

```powershell
git check-ignore -v backend/.env
git ls-files -- backend/.env
```

두 번째 명령 출력은 비어 있어야 한다. 새 설치라면 `Copy-Item backend/.env.example backend/.env`로 파일을 만들고 편집한다. 기존 `.env`는 덮어쓰지 않는다.

먼저 무해한 `https://example.com/`으로 설정된 제공자마다 최대 한 번 연결만 확인한다. URL 페이지를 직접 방문하지는 않는다.

```powershell
Push-Location backend
uv run python provider_smoke.py --live
Pop-Location
```

결과는 `docs/verification/providers.json`에서 `key_configured`, `attempted`, `status`를 확인한다. 키 값과 제공자 원문 응답은 저장하지 않는다. `/health` 성공은 키 정상 동작의 증명이 아니다.

전체 검증과 실제 비교를 함께 실행하려면 다음을 사용한다. API 비용이 발생할 수 있으며 실제 제공자 호출 시도 합계를 80회로 제한한다.

```powershell
powershell -ExecutionPolicy Bypass -File scripts/verify.ps1 -Live -MaxProviderAttempts 80
```

이미 Kotlin 결과가 최신이면 개별 비교도 가능하다.

```powershell
Push-Location backend
uv run python evaluation.py --mode live --max-provider-attempts 80
Pop-Location
```

`live-results.md`/`live-results.json`을 모의 결과와 구분해서 확인한다. 예산 초과는 `not_run_budget`으로 표시된다. 실제 시도 횟수는 캐시 재사용을 제외하고 따로 기록한다. 실패·시간 초과·키 문제도 확인한다. 도구는 제공자를 직접 호출한다. Google 위험 결과는 제공자의 남은 cacheDuration 안에서만 재사용하며 미등록 결과는 캐시하지 않는다. AI 성공 결과는 한 실행에서 최대 24시간 재사용한다. 운영 SQLite 캐시를 사용하지 않는 비교이므로 실제 앱 전체 통신 지연이나 warm cache 성능과 같지 않다.

합성 데이터의 `example` 도메인과 문서용 IP는 실제 악성 주소가 아니다. Safe Browsing 미등록이 예상되므로 이 실행으로 실제 악성 사이트 DB 재현율을 입증할 수 없다. 실사용 자료를 평가하려면 동의·비식별화·출처 검증·별도 라벨링이 선행돼야 한다. 입력 안의 링크·APK·단축 주소를 직접 열거나 설치하지 않는다.
