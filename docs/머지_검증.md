## 충돌 해결과 기존 변경 보존

| 파일 | 통합 내용 |
|---|---|

| `detect/Detector.kt` | 새 coordinator·사건별 경고·동의 처리를 유지하면서 PR #13의 위험 URL 재경고를 통합 |

위험 URL 재경고는 유효한 로컬 판정 캐시를 읽으며 외부 요청을 추가하지 않는다. 같은 URL을 새 사건에서 받으면 2점 미만이어도 캐시가 유효한 동안 경고한다. Google 결과는 제공자 TTL 이내, AI는 최대 5분이며 최대 500개다. Google의 유효시간을 넘는 영구 위험 기억 목록은 만들지 않는다. 만료 후에는 일반 후보 조건을 적용한다. 동의를 철회하면 새 자동 외부 요청을 중지하며 이미 기기에 남은 유효한 위험 근거의 경고는 유지한다.

기존 500개 퇴출 회귀 시험을 실제 coordinator 경로에 맞춰 옮겼다. 캐시 조회 자체가 요청을 하지 않는지, 정상 판정을 위험으로 읽지 않는지, Google TTL 만료 때 기억이 사라지는지 시험을 추가했다. 통합 후 Android 테스트는 이전 작업 브랜치의 44개에서 46개가 됐다.

## 유지되는 한계와 배포 후속 작업

- 실제 휴대폰·에뮬레이터 시험, Google·OpenAI 실제 탐지 성능은 미측정이다. 합성 자료 독립성 한계와 남은 오탐·미탐도 그대로다.
- 평가는 개별 문장의 초기 후보 조건(2점+URL)을 비교한다. 이전 사건의 유효 캐시가 있는 저점수 URL을 다시 받는 상황은 별도 회귀 시험이며 합성 정확도 수치에 합산하지 않았다.
- 저장소 머지는 Cloud Run 서버 배포가 아니다. 기존 HTTPS 주소는 유지했지만 서버의 새 `/check/details` 배포·실제 연결은 실행하지 않았다. 팀이 백엔드를 먼저 배포한 뒤 키 설정·연결 검사를 수행한다. 상세 API가 없는 서버에서는 추가 검사 불가로 처리하고 로컬 경고를 유지한다.
- `.env`·키·DB·APK 파일은 Git에 포함하지 않는다. APK 해시와 검증 기록만 포함한다.
