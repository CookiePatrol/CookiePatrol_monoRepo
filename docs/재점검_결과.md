# 심사 의견·PLAN 재점검 결과

2026-11-16, 첨부 심사 의견서 이미지 **네 장을 다시 열어** 원문과 `PLAN.md`, 구현·테스트·보고서를 대조했다. 심사위원의 핵심 요구는 실기기·오탐/미탐 검증, 권한 안내, AI 역할과 규칙 근거, 공식 자료, 구체적 협업과 월별 일정이다. 코드에서 보완 가능한 결함을 수정했다. **실기기·독립 데이터·실제 외부 API 검증까지 완료한 상태는 아니다.**

기준 브랜치는 `feature/backend-check-api`, 검증 당시 HEAD는 `70923b46037a166bf3cc6c6fa248d4f764f60f8c`다. 아래 결과는 커밋 전 작업 트리의 스냅샷이며 이후 커밋·push 여부는 Git 기록으로 확인한다. 원격 main을 병합한 검증은 아니다. 앱은 `0.2.1(3)`이다.

## 평가 결과에서 바로잡은 해석

전체 120개는 개발용 60개와 평가용 60개이며, 각각 정상 30·피싱 의심 30인 **합성 데이터**다. 개발 문구 N14↔평가 EN11·EN24, N15↔EN12, N26↔EN06은 표현이 달라도 같은 안내 시나리오의 변형에 가깝다. 자동 4-gram 기준은 이 의미 유사성을 잡지 못했다. 독립 작성·검토가 없으므로 분리 파일만으로 독립성이 확보되지 않는다.

| 합성 로컬 회귀 시험 | 원본 TP/FP/TN/FN | 수정 TP/FP/TN/FN | 해석 |
|---|---|---|---|
| 원래 평가용 60개 | 20/4/26/10 | 20/1/29/10 | 해당 문장의 오탐 3개 감소. 미탐 10개는 그대로. 독립 성능 개선 증거 아님 |
| 관련 정상 ID 4개를 사후 제외한 56개 | 20/0/26/10 | 20/0/26/10 | 추가 개선 효과 없음. 어려운 정상 사례 제외로 생긴 선택 편향이 있어 대표 정확도로 발표 불가 |

60개 결과를 더 좋게 만들기 위한 데이터 교체나 가중치 재조정은 하지 않았다. 새 평가는 개발 문구를 보지 않은 팀원이 별도 작성하고 두 명 이상 라벨 검토 후 고정해야 한다. 현재 결과의 계산식·분모·오탐/미탐 ID·후보 조건·시나리오별 근거는 [실행 결과](evaluation/mock-results.md)에 유지한다.

외부 구성 비교는 **모의 시험**이다. 모의 AI가 보완/악화하도록 지정한 사례는 실제 모델의 관측이 아니다. 실제 Google·OpenAI 탐지 성능은 미측정, 실제 외부 요청은 0회다. 지연 역시 로컬 Windows JVM 값이며 휴대폰 성능/배터리 결과가 아니다.
